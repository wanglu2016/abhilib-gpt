# 命題譯讀

把一句毘曇中文轉成一個可複覈的解釋。打開研究頁，左邊選書中原句，右邊看從公式讀回來的中文。可以改句、補語境、比較不同讀法、下載完整的 Lean 文件，或在本機保存審讀意見。[在線工具](https://wanglu2016.github.io/abhilib-gpt/translate/)

## 直接查術語

輸入「色界」會列出兩個可選的正式名。輸入完整名稱可以直接查看型別，下載可編譯的術語檔案。

| 正式名 | 在公式中表示什麼 | 可試的輸入 |
| --- | --- | --- |
| `三界.色界` | 三界中的一個值，可填入生地或所繫。 | 三界.色界不等於三界.欲界 |
| `十八界.色界` | 判別一法是否屬於十八界中的色境。 | 十八界.色界等於十二處.色處 |
| `心不相應行.得` | 判別一法是否為得法。見《俱舍九題》第 36 頁。 | 心不相應行.得是心不相應行 |
| `得捨.得`、`二修.得修` | 前者表示於該時取得一法，後者取修定中得修的意思。兩者都需要一個人位和一個法。 | 比較「不還者得捨.得初靜慮」與「不還者二修.得修初靜慮」 |

公式與語法樹保留正式名稱。Lean 4.19 的識別字以 `« »` 包住各段，例如 `«十八界».«色界»`。詞表可宣告一個類別、記錄一項原始關係，也可將一個術語定義為已有條件的組合。點開「所用術語與關係」可檢查其型別。[共用分類](../../AbhiLib/分類.lean) · [譯讀定義](../../AbhiLib/譯讀.lean)

## 用什麼檢驗它

先打開第 3 例「有業道非業」。刪掉「有」再按「轉成公式」。原句只需舉出一個業道而非業的例子。改句要求每一個業道都非業。如果在一個測試情形中有兩例業道，一例是業、另一例非業，原句成立，改句不成立。

再試「阿那含只成就無漏初靜慮」。工具會要求限定「只」。設想檢驗用的一個人位，兼成就有漏、無漏初靜慮，未成就其餘三地的無漏靜慮。固定初靜慮而排除有漏，這個人位違背句意。固定無漏而排除另外三地，這個人位符合句意。這個假設情形只用來區分兩種解釋。可在頁面比較兩種候選反譯和公式。

第 9 例取第 140 頁的條件句。書中前後文給出了「餘」相對的定地及「得」的得修義。工具保留習修、得修以及一般的得三個關係。另附第 139 頁「修淨非無漏」供對照，節取四句中的一格。書頁給出了定地和問答結構，打開該片段時頁面會把這兩項列入上下文。「清除上下文」後，兩項都須重新決定。如果取「列舉一格」，公式接受一個人位返回一個判斷。取「至少有一個這樣的時位」，才產生一個存在命題。其他例句直接從輸入解析。每例的出處、書頁和是否節引都在[樣本目錄](cases.mjs)。

## 公式裏的對象

| 記號或字段 | 所表示的對象或關係 |
| --- | --- |
| `法` | 研究範圍內、容許情形中的法的個例。按一生中實際出現過的法取值，會改變「能」的含義。 |
| `人位` | 一位有情在某一時位。用同一個變元表達條件前後的人與時間相同。 |
| `所繫`、`生地` | 分別給出法的繫屬與有情的生地。法的繫屬可以為空。 |
| `成就`、`現前`、`得捨.得` | 成就、現前、得分別建模。「成就甲類法」展開為在同一人位至少成就該類的一法。 |
| `無間生 a b` | 在同一相續中許可前念 a 無間生後念 b。類與類之間能相生，展開為存在這樣的一對。 |
| `∀`、`∃`、`¬`、`→`、`↔` | 分別表示每一個、至少一個、否定、推出、雙向推出。 |
| `Prop` 與 `人位 → Prop` | 前者是一項判斷。後者給出判斷條件，代入某個人位後纔得到判斷。 |

詞表給出類型、字形、釋義和 Lean 展開式。例如「無記」展開為有覆無記或無覆無記，「上界有情」展開為生色界或生無色界。「業」「業道」等仍是要由研究者解釋的基本分類。模型保留二者的外延供比較。這裏尚未給出全部基本分類的教理判準，也沒有把一個讀法自動登記為已證定理。

## 覆蓋範圍和擴展

目前能組合的表達包括泛稱、存在、否定、範圍明確的並列、兩類等同、必要與充分條件、成就及其例外、可能或禁止的無間相生、三性分別有例，以及有語境的修定省略句。簡繁文字共用同一詞表。整句須能解析。新詞、未支持句式、否定中範圍不清的並列都有顯式反饋。系統僅能提示已識別的歧義，成功解析的句子仍可能誤讀。

從新書頁增加例句時，先試自由輸入。如果已有詞義和構式足夠，只需把書頁、引句、上下文錄入 `cases.mjs`。新概念進入 `vocabulary.mjs`，需要新的對象或基本關係時擴展 `AbhiLib/譯讀.lean` 或共用的 `AbhiLib/分類.lean`，運行 `python3 tools/build.py` 同步瀏覽器用的聲明。新構式在 `grammar.mjs` 中組合原有量詞、謂詞和關係；同時增加改變一處措辭就改變意思的測試。`logic.mjs` 檢查變量和類型，從樹生成三種輸出。解析器不讀取樣本表、編號、頁碼或預寫的目標公式。

## 本地使用

在倉庫根目錄運行，瀏覽器打開終端所示地址的 `/translate/` 路徑。模塊、樣本和轉換都在本機，查原書和訪問 GitHub 需要聯網。

```sh
python3 -m http.server 8000 --directory docs
```

命令行使用 Node.js 18 以上版本；最後兩行另需倉庫鎖定的 Lean 4.19.0 在 PATH 中。

```sh
node tools/translate.mjs '有些業道不是業'
node tools/translate.mjs '阿那含只成就無漏初靜慮' only=levels --lean
node tools/translate.mjs --demo-lean > Readings.lean
lean Readings.lean
node tools/test-translate.mjs --lean
```

常規的 `python3 tools/build.py --check` 也運行譯讀測試。在小模型中比較兩種讀法，再把十個例子編譯為 Lean 定義，檢查代表性公式能否作為推理的前提使用。機器可以檢查公式的類型與推理是否有效；「原文在這裏恰好意指這條公式」留給審讀。批註可導出為 JSON，包含送審原句、語境選擇與公式。

# AbhiLib 毘曇庫

**一個可以復算的有部阿毗達磨形式化研究初版。** 打開研究頁，可以從一句原文進入 Lean 命題，查看證明所需條件，再撤去一項條件，檢查是否出現反例。

## 正式術語

法類與關係採繁體中文名，同形異義按所屬分類限定。例如 `三界.色界` 是界名，`十八界.色界` 判別一法是否屬色境。輸入一個「色界」可並排看兩個義項。Lean 4.19 的可編譯寫法是 `«三界».«色界»`。研究頁的 S、P、H、T 等編號可沿用；引用舊版英文 Lean 聲明的程式須改用繁中名。[比較「色界」兩義](https://wanglu2016.github.io/abhilib-gpt/translate/#sejie) · [共用分類](AbhiLib/分類.lean) · [譯讀定義](AbhiLib/譯讀.lean)

## 從一句中文開始

[打開獨立的命題譯讀工具](https://wanglu2016.github.io/abhilib-gpt/translate/) · [輸入自己的命題](https://wanglu2016.github.io/abhilib-gpt/translate/#new)

左欄十例摘自王路《俱舍九題》，每條可打開電子書對應頁。輸入框接受簡體、繁體和改寫句。以第 3 例為例，刪掉「有業道非業」的「有」再轉換，比較究竟是在說某些業道，還是在說所有業道。第 9 例可以清除書頁提供的上下文，自行判斷「餘」排除什麼、「得」取何義。還可點開同段的「修淨非無漏」，區分列舉一種情形與斷言它有實例。

程序用詞表和句法把輸入組裝成帶類型的邏輯樹，從同一棵樹生成公式、中文反譯和 Lean 文件。頁面會顯示必要的解釋選擇。尚未覆蓋的說法會顯示卡在哪一步。你可以逐句批註並導出記錄。[實現、適用範圍與複覈方法](docs/translate/README.md)

## 從第 46 步開始

王路《怎樣推導出一個毘曇命題？》（2022年7月）問「有覆無記色唯初靜慮繫」怎樣推出。第 46 步判定有覆色是表，原文引前提 11 和第 43 步。色業分表、無表，已知某色不是無表，還須知道它屬於色業。第 45 步恰好給出了這一點。對照該步的原文、形式化說明和實際傳參即可檢驗。[第 46 步](https://wanglu2016.github.io/abhilib-gpt/#S46) · [完整組裝](https://wanglu2016.github.io/abhilib-gpt/#T24)

項目保留16條前提、48個編號步驟、作者所附相關頌，以及三條證明路線。長證有47個步驟以 Lean 定理編碼，第30步以表色子類型到色法的投影編碼。三個分類前提 P04、P11、P14 由斷類、色業、染性的定義承載。P05 支持第2–4步支線。其餘12條在原次序的最終定理中以參數出現，此外還有5項明確標出的建模條件。閱讀頁面可切換簡繁，作者原句和 Lean 代碼始終保留原貌。

## 在本地複覈

安裝 [Lean / Elan](https://lean-lang.org/install/) 、Python 3 和 Node.js 18 或以上版本，進入倉庫。項目鎖定 Lean 4.19.0。命題譯讀工具沒有第三方 JavaScript 依賴。

```sh
python3 tools/build.py --check
lake env lean tools/Transfer.lean
```

第一條命令編譯證明，逐條檢查所依賴的全局公理，覈對編號和引用，從 Lean 導出112個候選模型描述及三張得心名冊，並檢查網頁是否為同一份結果。第二條命令驗證十個遷移小題。提交和拉取請求使用同一組命令。直接雙擊 `docs/index.html` 可離線閱讀證明工作臺。命題譯讀工具請使用下述說明中的本地 HTTP 入口。編輯條目後運行 `python3 tools/build.py` 重建頁面。

## 如何擴展

1. 在 `AbhiLib/` 建立局部理論，分別定義對象、關係、經論立場與額外解釋條件。用穩定編號組織自然語言與形式聲明。
2. 給命題寫出 Lean 證明，或給出滿足背景而違反結論的模型。能做到兩者中的哪一步，就登記到哪一步。
3. 將新模塊導入 `AbhiLib.lean`，在 `data/entries.tsv` 登記聲明、出處和解釋範圍，相關術語寫入 `data/concepts.tsv`。分類、定義、推導、文本歸屬分別審覈。操作細節見 [維護約定](AGENTS.md)。

當前模型壓縮了無色四地，並單列不繫。五項橋接是這版編碼所需的解釋條件，尤其第32步如何把「同染」細分到「同為有覆」，以及親發心的適用範圍，均待義理審讀。四條簡化規則各自有刪除反例，只說明該固定小模型中的不可刪性。全文獻的最小前提集仍待研究。
